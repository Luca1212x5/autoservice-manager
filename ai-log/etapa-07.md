## What I learned / what did not work
I learned the "server first, state second" pattern: waiting for `await createInterventie(...)` or `await updateInterventie(...)` to resolve before updating React state ensures the UI only reflects confirmed data and uses the ID generated by the server. I also saw why keeping the form inputs populated inside the `catch` block is essential when the API goes offline, allowing the user to retry without retyping. Finally, I learned how automated end-to-end tests locate elements in the DOM using `data-testid` and `data-id` attributes alongside a root `tw.json` schema.
